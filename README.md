# Bubble · 端到端加密临时聊天

自托管、零依赖的端到端加密临时聊天。服务端只转发和存储密文，永远看不到聊天内容。

## 功能

- **端到端加密**：浏览器本地加解密，密钥/密码永不上传，服务端只收到房间号与密文。
- **零门槛进房**：点击 LOGO 创建加密房间；或粘贴分享链接进房。无注册。
- **临时会话**：文字、图片、文件、语音消息传输；在线人数实时显示；房间可清空 / 退出；超大房间首访自动瘦身。单条文字约 96KB，单个附件约 48MB，每个房间最多 100 个附件、总计约 1GB。
- **单文件部署**：前后端 + 静态资源为 `bubble.phar`，UIGG 框架走 `https://ui.gg` CDN。

## 用法

**1. 上传到服务器（网站根目录只放这两个文件）**

- `index.php` —— 入口引导
- `bubble.phar` —— 单文件应用

> ⚠️ `rooms/` 首次访问自动生成，需 PHP 对该目录有写权限。

销毁房间后会短暂保留 `.burned` 墓碑（30 秒；最迟在下一轮清扫时移除），用于拦截迟到请求重建房间；后续请求触发清扫后自动删除。

建议将 `rooms/` 放在网站可访问目录之外；若必须放在网站根目录下，请在 Web 服务器中禁止直接访问 `rooms/`、`.json` 和 `.files` 路径。即使内容是密文，也不应把房间文件暴露为静态资源。

**2. 配置伪静态（前端控制器，必需）**

所有请求必须交给 `index.php` 从 phar 内读取，否则静态资源 404。

nginx（宝塔「伪静态」框直接粘贴）：

```
if (!-e $request_filename) {
    rewrite ^ /index.php last;
}
```

Apache（网站根 `.htaccess` 或伪静态框）：

```
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [L]
```

**3. 点 LOGO 建房间或粘贴邀请链接进房。建议全程 HTTPS。

## 语音消息

点输入框旁的麦克风按钮（`.ico-mic`）开始录音，按钮变红并旋转；再次点击停止并发送。录音在浏览器本地加密后复用附件上传 / 销毁管道，服务端只存储密文，零知识属性不变。

- **时长上限**：单条语音硬上限 3 分钟，到点自动停止并发送（`chat.js` 中 `MAX_VOICE_MS` 可调）。
- **录制格式**：使用浏览器原生 `MediaRecorder`，零额外依赖。苹果设备录 `mp4/aac`，Win / 安卓录 `webm/opus`。
- **播放**：接收方用原生 `<audio>` 播放器收听；若设备不支持该编码（典型如苹果设备收到 Win / 安卓的 `webm/opus`），自动降级为「下载语音」链接。
- **兼容性说明**：苹果录的 `aac` 全平台可播；仅「Win / 安卓录 → 苹果收」这一跨生态路径需走下载兜底。

## 免责申明

- 端到端加密保护「内容」，但不隐藏「谁在与谁通信」的元数据；公网部署务必启用 HTTPS。
- 房间密钥仅存在于分享链接的 `#` 片段，链接一旦泄露即等同于泄密，请仅通过可信渠道分享。
- 服务端为无状态传输 / 存储中继，运营方无法读取内容，但可按规则处置存储文件（封禁 / 删除房间）。
- 依赖浏览器 WebCrypto 与 `https://ui.gg` CDN：浏览器过旧或 CDN 不可达将导致功能失效。
- 本工具作者不对任何数据丢失、泄露或滥用负责；请仅在合法、双方知情同意的场景下使用。
